# 🛡️ Ensiklopedia 81 Serangan Siber & Cara Pencegahan

Sebagai seorang pengamal keselamatan siber (*Cyber Security Practitioner*), memahami kepelbagaian vektor serangan adalah wajib. Berikut adalah senarai lengkap penerangan dan cara pencegahan selari dengan falsafah *Secure-by-Design* (Protokol Abu Hanifah):

| No | Nama Serangan | Penerangan Ringkas | Cara Pencegahan Utama |
|:---|:---|:---|:---|
| 1 | **Broken Access Control** | Pengguna biasa berjaya melepasi had dan mengakses fungsi/data admin. | Laksana semakan kuasa (*Role-Based Access Control*) pada setiap titik akhir (API/Route). |
| 2 | **Security Misconfiguration** | Tetapan lalai (*default*) sistem dibiarkan terbuka (cth: mod *Debug* didedahkan). | Kunci pelayan (*Hardening*), matikan paparan ralat terperinci, prinsip *Deny by Default*. |
| 3 | **Software Supply Chain Failures** | Perpustakaan pihak ketiga (*npm/composer*) yang dimuat turun telah dijangkiti *malware*. | Imbas kebergantungan (cth: `npm audit`), semak fail *lock*, dan laksana *Software Bill of Materials* (SBOM). |
| 4 | **Cryptographic Failures** | Maklumat sensitif (seperti kata laluan) disimpan dalam format teks biasa (*plaintext*) atau guna penyulitan usang (MD5/SHA1). | Gunakan AES-256-GCM, Bcrypt/Argon2 untuk kata laluan, wajibkan HTTPS (TLS 1.2+). |
| 5 | **Injection** | Kemasukan blok arahan/kod musuh ke dalam sistem. | Pengesahan input (*Input Validation*) yang ketat, dan gunakan penapis terbina (*parameterization*). |
| 6 | **Insecure Design** | Aplikasi direka tanpa sebarang pelan keselamatan sejak dari awal. | Budayakan *Threat Modeling* sebelum menulis kod (Falsafah *Secure-by-Design*). |
| 7 | **Authentication Failures** | Kelemahan pada sistem pengurusan log masuk/sesi (cth: sesi tidak luput, kata laluan lemah). | Laksana Pengesahan Pelbagai Faktor (MFA) dan polisi kerumitan kata laluan. |
| 8 | **Software or Data Integrity Failures** | Kod atau data diubah suai tanpa dapat dikesan (integriti rosak). | Gunakan tandatangan digital (*Digital Signatures*) pada setiap kemaskini / bungkusan (patch). |
| 9 | **Security Logging and Alerting Failures** | Ketiadaan rekod audit (*log*) yang jelas apabila berlaku serangan pencerobohan. | Laksana pemantauan berpusat (*Centralized Logging*) pada semua aktiviti sensitif (Log Masuk Gagal, Transaksi Wang). |
| 10 | **Mishandling of Exceptional Conditions** | Sistem ralat *(crash)* dan membocorkan paparan jejak timbunan (*stack trace*) secara terperinci kepada klien. | Gunakan blok `try-catch` secara berpusat, kembalikan ralat generik (contoh: "Ralat Dalaman"). |
| 11 | **API Key Leaks** | Kata laluan atau Kunci API tertiris/terbocor di *Github* atau *Frontend*. | Asingkan konfigurasi menggunakan fail `.env`, guna Pengurus Rahsia (*Secret Manager* AWS/GCP). |
| 12 | **Account Takeover** | Penjenayah merampas hak milik akaun pengguna asal. | Hadkan percubaan gagal (*Rate Limiting*), beku akaun sementara, pemantauan log masuk IP asing. |
| 13 | **Brute Force Rate Limit** | Serangan tekaan kata laluan/OTP secara membabi buta dan bertalu-talu. | Integrasi Cloudflare Turnstile, ReCAPTCHA, dan laksana tetingkap had kadar (*Sliding Window Rate Limit*). |
| 14 | **Business Logic Errors** | Logik perniagaan dimanipulasi (cth: meletakkan harga negatif dalam bakul untuk mendapat duit percuma). | Semak semula had, nilai, dan turutan logik di bahagian *Backend* (jangan pernah percayai klien). |
| 15 | **CORS Misconfiguration** | Tapak web lain diberi kebenaran membaca data kerana tetapan asal *Cross-Origin* `*` (Wildcard). | Tetapkan spesifik domain `Access-Control-Allow-Origin` (Jangan guna `*`). |
| 16 | **CRLF Injection** | Menambah pemecah baris tersembunyi `\r\n` untuk memanipulasi *Header HTTP* balasan. | Nyahjangkit (*Sanitize*) kesemua *header* buatan pengguna sebelum dikembalikan. |
| 17 | **CSS Injection** | Skrip gaya digunakan untuk mencuri ketukan papan kekunci (Keylogger CSS). | Bersihkan *markup* menggunakan *DOM Purify* yang membuang tag `style`. |
| 18 | **CSV Injection** | Penulisan formula makro ke dalam hamparan (Excel/CSV) yang membahayakan komputer mangsa. | Tambah simbol ` ' ` (Apostrophe) di hadapan mana-mana data yang bermula dengan `+`, `-`, `=`, `@`. |
| 19 | **CVE Exploits** | Eksploitasi kerentanan versi lama pihak ketiga yang umum diketahui. | Penampalan kerentanan berjadual (*Patch Management*) dan semakan audit automatik. |
| 20 | **Clickjacking** | Pengguna ditipu klik butang tersembunyi (melalui bingkai *Iframe* telus). | Tambah *header* respon `X-Frame-Options: DENY` atau CSP `frame-ancestors`. |
| 21 | **Client Side Path Traversal** | Mengarah aplikasi klien mengekstrak sumber fail tempatan. | Sahkan laluan klien dan tolak aksara `../` di peringkat pelayar. |
| 22 | **Command Injection** | Memaksa OS pelayan menjalankan perisian/perintah secara paksa (cth: melalui `system()` PHP). | Elakkan fungsi *shell execution*, gunakan API terprogram (SDK). |
| 23 | **Cross-Site Request Forgery (CSRF)** | Pengguna dipaksa tanpa sedar menghantar tindakan menukar kata laluan/wang. | Wajibkan token anti-CSRF pada setiap borang `POST` dan aktifkan kuki `SameSite=Lax/Strict`. |
| 24 | **DNS Rebinding** | Penyerang menukar alamat DNS secara dinamik untuk menembusi pertahanan tembok api (Firewall). | Pelayan mesti menolak HTTP *Host header* yang pelik dan menetapkan pengesahan nama Hos yang tepat. |
| 25 | **DOM Clobbering** | Kekeliruan nama *ID* HTML mengubah skrip logik Global `window`. | Jangan rujuk elemen HTML sebagai pembolehubah *Global*. Guna kaedah `document.getElementById()`. |
| 26 | **Denial of Service (DoS)** | Pelayan dilumpuhkan akibat banjir permintaan data. | Gunakan proksi CDN (Cloudflare), sekatan (Rate Limit), Web Application Firewall (WAF). |
| 27 | **Dependency Confusion** | Penyerang memuat naik pakej Awam bernama sama untuk menimpa pakej Dalaman/Privat anda. | Ikat ketat ruang nama pakej (*Scope/Namespace*) pada storan repositori tertutup peribadi. |
| 28 | **Directory Traversal** | Pemintas membaca fail rahsia (cth: `../../etc/passwd`). | Gunakan fungsi `realpath()`, bersihkan input `/`, `.`, dan laksana *Whitelist* nama fail. |
| 29 | **Encoding Transformations** | Pengekodan berganda (*Double URL Encode*) bagi membolosi penapis keselamatan. | Nyahkod (*Decode*) input sepenuhnya dahulu sebelum sebarang penapisan keselamatan dijalankan. |
| 30 | **External Variable Modification** | Pembolehubah kritikal dari luar sistem diolah secara haram. | Jangan pernah membina logik bergantung kepada pembolehubah luaran tanpa ikatan tetap (*Strict Binding*). |
| 31 | **File Inclusion (LFI/RFI)** | Modul dalaman pelayan melarikan fail jahat tempatan atau luar rangkaian. | Matikan penetapan laluan dinamik `include()`, dan bina matriks senarai putih pemetaan fail mutlak. |
| 32 | **Google Web Toolkit** | Isu deserialisasi kerangka Java legasi (GWT). | Laksanakan proses migrasi aplikasi ke kerangka pelayan terkini (Modern Frontend). |
| 33 | **GraphQL Injection** | Klien mengekstrak kuantiti pangkalan data ekstrem secara infiniti bersarang. | Hadkan kedalaman graf (*Depth Limiting*), tutup ciri *Introspection* GraphQL di persekitaran Produksi. |
| 34 | **HTTP Parameter Pollution** | Parameter pelayan berganda dihantar sekali gus memeningkan WAF dan pelayan (`?id=1&id=2`). | Sentiasa laksana ketetapan parameter pertama atau parameter terakhir sebagai rujukan berkuasa. |
| 35 | **Headless Browser** | Memanipulasi skrip *Puppeteer/Selenium* (Cetak PDF) untuk memuat turun sumber dalaman pelayan. | Asingkan eksekusi pelayar bot di dalam bekas *(Sandbox/Docker)* dan matikan akses laluan LAN. |
| 36 | **Hidden Parameters** | Klien menukar atribut Input form `type="hidden"` (cth: tukar harga tersorok). | Nilai pengiraan wajib ditarik terus dari Pangkalan Data (pelayan), bukan *input* tersorok pengguna. |
| 37 | **Insecure Deserialization** | Pelayan memecahkan format kod berniat jahat semasa nyah-serial. | Haramkan pemakaian `unserialize()`, sebaliknya sentiasa amalkan format data `JSON`. |
| 38 | **Insecure Direct Object References (IDOR)** | Klien mengakses rekod pelanggan lain menukar param ID (`/invoice?id=123`). | Sistem wajib menyemak pemilikan ID rekod bersama ID Sesi (Auth) atau ubah siri angka ke *UUID v4*. |
| 39 | **Insecure Management Interface** | Log pentadbir (Admin Panel / phpMyAdmin) tidak disembunyikan. | Dedahkan ia secara Eksklusif untuk alamat IP Whitelist/VPN korporat sahaja. |
| 40 | **Insecure Randomness** | Fungsi pengundian `rand()` diteka oleh penyerang akibat ketidakseimbangan algoritma (Entropi Lemah). | Gunakan `CSPRNG` (Cryptographically Secure PRNG) cth: `random_bytes()` di PHP. |
| 41 | **Insecure Source Code Management** | Direktori reka sumber `.git/` terbuka awam membolehkan penyerang memuat turun pangkalan kod asal. | Sekat permintaan bermula aksara `.` di NGINX/Apache dan padamkan fail SCM sebelum ke pelayan Produksi. |
| 42 | **JSON Web Token (JWT)** | Kelemahan tandatangan seperti *None Algorithm* meniru identiti JWT admin. | Paksa aplikasi sentiasa merujuk *Algorithm* kukuh, abaikan struktur `alg: none`. |
| 43 | **Java RMI** | Rangkaian penyambung memori kaedah legasi *(Remote Method Invocation)* dimanipulasi. | Wajib halang pendedahan *port* luaran dan elakkan perkhidmatan RMI sekiranya tidak penting. |
| 44 | **LDAP Injection** | Suntikan sintaks pada Active Directory bagi memintas pengesahan (seakan SQLi). | Parameter/Nilai hak akses wajib dibersihkan, menggunakan penapisan fungsi lalai `LDAP Escape`. |
| 45 | **LaTeX Injection** | Sistem menjana PDF menerusi `pdflatex` dipaksa lari baris arahan pelayan tersembunyi. | *Sandbox* pelaksanaan LaTeX tanpa izin bacaan OS. Matikan *`write18`* (larangan Command exec). |
| 46 | **Mass Assignment** | *JSON Payload* terus mengubah nilai Model secara massa (termasuk nilai `is_admin=true`). | Terapkan reka bentuk OOTB (`fillable`/`guarded` atribut) dan gunakan DTO terhad *Data Transfer Objects*. |
| 47 | **Methodology and Resources** | Mengeksploitasikan fail sumber lebihan dokumentasi terbiar (`README.md / phpinfo()`). | Wujudkan pengintegrasian CD/CI paip untuk membersihkan sisa binaan sebelum diangkat awam. |
| 48 | **NoSQL Injection** | Mengawal pangkalan Data NoSQL (MongoDB) mengguna rantaian logik *Operator Json* (cth: `$ne`). | Amalkan corak ketat (`Strict Type Binding`) dan sanitasi blok JSON pemprosesan kunci objek awalan `$`. |
| 49 | **OAuth Misconfiguration** | Pemintasan Log Masuk (Social Login) dengan mencedok kelemahan Token OAuth2. | Sentiasa semak padanan `redirect_uri` secara tepat dan sertakan parameter kripto berantai pengesahan `state`. |
| 50 | **ORM Leak** | Celah pendedahan Model kepada JSON API yang turut menyelit maklumat rahsia (Hash Kata Laluan). | Teguhkan corak pengabaian atribut (*Hidden Properties*) dan gunakan DTO pengubah API. |
| 51 | **Open Redirect** | Sistem mengalihkan pengguna ke laluan yang tak disemak berpunca nilai manipulasi Input param `?next=`. | Sahkan nilai penghalaan luaran; arahkan kembali ke Domain utama pelayan sekiranya domain param tak serasi. |
| 52 | **Prompt Injection** | LLM dipaksa melanggar etika dasar bot apabila pengguna mengubah format arahan tersembunyi. | Penguatkuasaan pengawal sistem (*Guardrails AI*) dan pemeriksaan keluaran/masukan pangkalan data AI LLM. |
| 53 | **Prototype Pollution** | Penyatuan struktur asas JavaScript (Proto) dieksploit secara bersarang untuk merubah tingkah laku JS global. | Matikan penggabungan tak terhad `deep_merge` dan wajib pelihara rantaian awalan guna perlindungan `Object.freeze()`. |
| 54 | **Race Condition** | Masa urusan logik terhimpit akibat bebanan konkurensi menyebabkan pendua wang/stok. | Enjin wajib mempunyai *Mutually Exclusive* atau transaksi berstatus `Row-Level Lock (SELECT FOR UPDATE)`. |
| 55 | **Regular Expression (ReDoS)** | Padanan struktur *Regex* rumit (mengandungi rekursif melampau) menyebabkan CPU pelayan mencanak naik ke 100%. | Guna sintaks Regex tanpa corak lewah berganda, dan pasangkan had masa (*Timeout*) ketika pemprosesan Regex. |
| 56 | **Request Smuggling** | *Payload Header HTTP* meragukan mengganggu lapisan Pemproses Proksi sehingga terpecah ke sesi pengguna lain. | Samaratakan logik antara pelayan utama dan laluan *CDN Proksi*, dan menolak `Transfer-Encoding` rosak. |
| 57 | **Reverse Proxy Misconfigurations** | Kebergantungan buta-buta alamat IP klien dari parameter `X-Forwarded-For` rekaan proksi penceroboh. | Hanya pertimbangkan nilai `X-Forwarded-For` dari alamat Proksi sah yang anda sendiri miliki (contoh `Trusted Proxies`). |
| 58 | **SAML Injection** | XML maklumbalas palsu Identiti Pengesahan SSO (Single Sign On) dirungkai bagi menipu keabsahan token. | Tandatangan XML wajib dilakukan semakan (*Validation Check*) dan pemprosesan DTD mesti dihentikan (halang XXE). |
| 59 | **SQL Injection** | Penggodam mencetak pemprosesan blok pertanyaan SQL bebas masuk ke pangkalan data rasmi. | Tolak terus penyambungan rentetan *string*. Mesti berteraskan *Prepared Statement / Parameterized Queries*. |
| 60 | **Server Side Include Injection (SSI)** | Serangan penulisan arahan dinamik secara langsung melalui sisipan `<!--#exec cmd="ls" -->` fail pelayan. | Buang penukaran kod berformat SSI daripada input, dan nyahaktif ciri pemprosesan *SSI Directive* modul pelayan web. |
| 61 | **Server Side Request Forgery (SSRF)** | Penceroboh "mengarahkan" pelayan mengakses intranet (*127.0.0.1*) sendiri melalui parameter memuat URL cth: imej awatar. | Buat senarai semak larangan akses IP peribadi (*Private IPs*) sewaktu pemanggilan rangkaian pelayan Webhook/CURL. |
| 62 | **Server Side Template Injection (SSTI)** | Aksara Templat `{{ 7*7 }}` (Twig/Jinja2) menjana logik sistem melangkaui pembalut enjin *Frontend*. | Pastikan pengguna sama sekali dilarang meletakkan sintaks *Templating* - nyahjangkit input melalui tapisan ketat *Sandbox*. |
| 63 | **Tabnabbing** | *Tab* belakang pelayar dilarikan ke laman perisian tebusan pancingan data (Phishing) apabila pengguna klik pautan laman baru. | Tambahkan semakan wajib atribut `rel="noopener noreferrer"` pada semua elemen navigasi pautan luaran `<a>`. |
| 64 | **Type Juggling** | Lemah perbandingan PHP di antara aksara (`"0e123" == "0e456"` memulangkan `True`). | Terapkan pembandingan operator mutlak/Ketat secara menular `===` atau `!==` yang membanding nilai + jenis serentak. |
| 65 | **Upload Insecure Files** | Kegagalan mengekang aplikasi menapis muatnaik jenis cengkerang (*Shell Backdoor PHP/ASP*). | Tapisan secara ekstensi (*Magic Bytes MIME*), letakkan pemuat naik di luar *root web* pelayan / laksana `chmod -x`. |
| 66 | **Virtual Hosts** | Menyeleweng pelayan menggunakan domain tidak didaftar memaksa pelayan mengemudi fail pelayan asas web lain. | *Bind* alamat laman rasmi melalui pendengaran *Vhost* yang khusus. Halang terus penyambungan blok `Host` lalai pelayan utama. |
| 67 | **Web Cache Deception** | Klien dibekalkan akses memori `Cache` rahsia pengguna lain memandangkan proksi *Cache* dikelirukan (cth `profil.php/a.jpg`). | Abaikan *caching* statik pada sumber rahsia dengan menetapkan respon keselamatan *Header: Cache-Control no-store*. |
| 68 | **Web Sockets** | Sesi kekal interaktif disalur tanpa pertahanan berikutan terlepas semakan identiti (Handshake websocket wss:// awal). | Sentiasa ikuti pemeriksaan rapi Auth Sesi (Ticket Auth / JWT) sejurus selepas menubuhkan sambungan WSS (*On-Connect*). |
| 69 | **XPATH Injection** | Pemintas menceroboh pengkalan data bertruktur XML (serupa SQLi versi data XML). | Manfaatkan pakej penyusunan logik secara terikat *Parameterized* API (Elak sisipan *String XPath* mentah). |
| 70 | **XS-Leak** | Rekod tindakbalas pemasaan (Timing Attack) direkod bagi mendedahkan perbezaan rahsia pelayan klien sisi rentas pelayar. | Halang integrasi paparan rentas Domain menerusi pertahanan pengepala *Cross-Origin-Opener-Policy (COOP)*. |
| 71 | **XSLT Injection** | Kerentanan memuat transformatif (*Stylesheets XML*) diisi kod tersembunyi berstruktur arahan (Code Exec). | Pengharaman prosesan helaian pengguna. Gunakan pustaka penukar yang telah dipanjangkan ciri kebal (*XML Secure Processing*). |
| 72 | **XSS Injection** | Suntikan pelayan pelanggan. Aksara bahasa *Frontend* dipaksa eksekusi pelayar mangsa lain (Curian Kuki `document.cookie`). | Enkod Output *htmlspecialchars*, buang teks bahaya menggunakan penulen DOM dan kuatkuasa pengepala `Content-Security-Policy`. |
| 73 | **XXE Injection** | Kemasukan XML rujukan Entiti Sistem Memori pelayan (`SYSTEM "file:///etc/passwd"`) membaca konfigurasi sulit dalaman. | Modul pelayan penganalisis XML (*Parser*) patut sentiasa dihentikan kemampuan menjejak Rujukan Luaran (Disable *External Entities*). |
| 74 | **Zip Slip** | Penyahmampatan Arkib (ZIP/TAR) dipasang struktur pautan melepasi pepohon laluan (*Directory Extraction Escape*). | Semua pengekstrakan wajib ditapis dengan pengujian bahawa laluan akhirnya memetakan ke direktori selamat sasaran sahaja. |
| 75 | **_LEARNING_AND_SOCIALS** | Kekhilafan kemanusiaan (Teknik Penipuan Kejuruteraan Sosial/Phishing). | Didikan, Latihan simulasi ancaman keselamatan Siber untuk staf dalaman yang peka dan memandu budaya kecurigaan positif korporat. |
| 76 | **_template_vuln** | Aplikasi kerangka *(Framework)* asas disyaki mempunyai lompong terbina di dasar akar model seni bina lama. | Teroka log tampalan, naiktaraf bingkai dan laksana analisis keselamatan kod Statik (SAST / Abu Hanifah Safeguard) seawal mungkin! |
| 77 | **Credential Stuffing** | Menggunakan data e-mel/kata laluan yang telah dibocorkan dari laman web lain untuk log masuk paksa. | Laksana Pengesahan Dua Faktor (MFA) dan bandingkan kata laluan dengan pangkalan data kerentanan terbuka (cth: HIBP). |
| 78 | **Man-in-the-Middle (MitM)** | Penggodam memintas di antara komputer klien dan pelayan di dalam rangkaian awam untuk mencuri sesi transit. | Kuatkuasa HTTPS secara mutlak (HSTS Strict) dan larang *Downgrade Attack* menerusi sijil keselamatan yang sah. |
| 79 | **Buffer Overflow** | Serangan memori OS di mana input melebihi ruang peruntukan menyebabkan arahan berniat jahat dieksekusi. | Gunakan bahasa pengaturcaraan yang *Memory-Safe* seperti **Rust**, atau aktifkan perlindungan memori OS (ASLR/DEP). |
| 80 | **Reentrancy Attack** | Serangan kontrak pintar Web3 (Blockchain) di mana fungsi pengeluaran dipanggil rekursif sebelum baki ditolak. | Amalkan reka bentuk semakan ketat *Checks-Effects-Interactions Pattern* untuk blok rekursi. |
| 81 | **Watering Hole Attack** | Daripada menggodam pelayan utama, penggodam meracun laman pihak ketiga yang kerap dikunjungi oleh mangsa/staf. | Bekalkan Endpoint Detection & Response (EDR) pada peranti staf dan tapis keselamatan trafik proksi korporat. |
