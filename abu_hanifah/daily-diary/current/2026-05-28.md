### Eksperimen Beban Ekstrem (150 VUs) & Perbandingan Frontend vs Backend
**Masa**: Petang (Sesi Lanjutan)

Tuan meminta perbandingan prestasi beban berasingan untuk melihat kontena mana yang lebih kukuh di bawah beban ekstrem **150 virtual users serentak (VUs)** pada spesifikasi pelayan 4GB RAM / 2 Cores:

1. **Ujian Beban Next.js Frontend (150 VUs)**:
   - **Keputusan**: **12,805 requests** diproses dalam 1 minit (kadar kelajuan 212.77 requests/saat).
   - **Error Rate**: **0.00%** (Tiada ralat langsung).
   - **Latency (p95)**: **96.41 ms** (Sangat pantas).
   - **Analisis**: Frontend Next.js sangat ringan dan stabil untuk melayani ratusan pengguna serentak kerana menyajikan fail HTML statik yang tidak membebankan pemprosesan CPU.

2. **Ujian Beban Laravel API Backend (150 VUs)**:
   - **Tindakan**: Had workers PHP-FPM dinaikkan (`pm.max_children = 100`) dan Rate Limit Nginx dilonggarkan (`rate=200r/s`, `burst=150`).
   - **Keputusan**: Ujian berjaya diselesaikan dengan **0.00% ralat** (ralat 503 berjaya dihapuskan sepenuhnya).
   - **Latency (p95)**: **14.53 saat** (Kelewatan yang tinggi disebabkan queuing).
   - **Analisis**: Backend memproses query pangkalan data dan logik perniagaan secara dinamik. Pada perkakasan 2 Cores CPU, 100 proses worker PHP-FPM terpaksa bersaing merebut kitaran CPU fizikal, yang menyebabkan waktu respons menjadi perlahan (*queuing bottleneck*) walaupun tiada ralat berlaku.

**Kesimpulan**: Frontend Next.js mampu melayani concurrent user jauh lebih tinggi berbanding backend Laravel pada had perkakasan (4GB RAM / 2 Cores) yang sama. Untuk backend melayani throughput tinggi dengan latency pantas, peningkatan CPU cores fizikal adalah perlu.

**Tindakan Akhir**: Semua container Vocabulary telah dimatikan sepenuhnya menggunakan `docker-compose down` dan `docker stop` untuk menyediakan sumber pelayan bagi projek **SaaS House**.

**Status Projek Vocabulary**: **160/160 task selesai sepenuhnya (100% Siap)**.
